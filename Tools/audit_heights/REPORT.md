# Аудит высот — какие экраны ломаются на разных высотах

Дата: 22.10.2026 · ветка `wt/audit-heights` (от `88f9cd2`) · код приложения не менялся · «Свет» пропущен (его переделывает wt/29-8v27).

## 1. Как мерили

- Сборка Debug этой ветки (`88f9cd2`, собрана Xcode 26.6), 57 сцен на каждую из 5 моделей, тема dark — 285 снимков и 285 файлов рамок узлов (`native.json`, точки окна). Скрипты: `Tools/audit_heights/run.js` (снимает), `analyze.py` (числа), `montage.py` (склейка кадров рядом).
- Модели (симуляторы `Audit-*`, iOS 26.5), размеры **замерены** (`size` + `safe` из рамок):

| модель | окно, pt | верх / низ безопасной зоны |
|---|---|---|
| iPhone SE 3 (нижняя граница) | 375×667 | 20 / 0 |
| 15 Pro | 393×852 | 59 / 34 |
| 17 Pro (= 16 Pro) | 402×874 | 62 / 34 |
| 15 Pro Max | 430×932 | 59 / 34 |
| 17 Pro Max (= 16 Pro Max, 18 Pro Max) | 440×956 | 62 / 34 |

  16 Pro по размеру = 17 Pro, 16 Pro Max = 17 Pro Max — отдельно не снимались.
- Светлая тема: на SE 3 и 17 Pro Max сняты 10 сцен (карта, свод карты, месяц, день, карточка, форма, настройки, документы, AR-слои, мудборд) — рамки всех узлов совпали с тёмной до 1 pt (20 пар «сцена × модель», 0 расхождений). Раскладка от темы не зависит; остальные сцены в light не снимались.
- **Duo (466×678 снаружи, 669×951 внутри) не снят**: симулятор iOS берёт только готовые модели, произвольный размер окна выставить нечем (ни `simctl`, ни `LP_SIM`). Строки Duo ниже — разбор по коду и по ближайшему замеру (SE 3 по высоте 667 ≈ внешний экран 678).
- Xcode за время работы обновился с 26.6 до 27.1 (Xcode.app изменён 21.10 в 23:12; потребовалась повторная лицензия). Runtime симулятора остался iOS 26.5; размеры и безопасные зоны **до и после обновления те же** (17 Pro Max: 440×860 + 62/34 в первом пробном прогоне на 26.6 и в полном на 27.1). Сборка приложения при этом осталась старая (26.6), под 27.1 не пересобиралась — поведение приложения под новым SDK не проверено.
- Вердикт «OK» значит: по рамкам и кадру ничего не обрезано без прокрутки и не накладывается. Вертикальная прокрутка считается нормой.

## 2. Итог по ширине находок

Главный вывод: **на линейке Pro (393×852 … 440×956) настоящих поломок почти нет** — почти все экраны лежат в `ScrollView` или считают место по измеренному окну. Поломки сидят на нижней границе (SE 3, ≈ внешний экран Duo), и две — на всех моделях: форма не знает безопасную зону сверху, панель вкладок не знает, есть ли полоса «домой». Устройство (Duo) ломается не высотой, а тем, что приложение вообще не знает про размерные классы и ориентацию (раздел 5).

## 4. Проблемы по важности (линейка Pro вперёд)

Усилие: small — до пары часов, medium — день, large — несколько дней.

**П1. Форма съёмки: верхняя полоса стоит на фиксированных 46 pt, безопасная зона сверху не учитывается.** Измерено: `form.close` y = 46 при верхней зоне 20 / 59 / 62 / 59 / 62 (все 5 моделей). У карточки, документов, организаций, мудборда та же кнопка стоит ровно на верхней зоне (59 / 62). Причина: `FormScreen.swift:54` (`padding(.top, 46)`) + `FormScreen.swift:90` (`ignoresSafeArea(.container, edges: .top)`). На Pro кнопки ✕ и ✓ уходят на 13–16 pt вверх, в зону часов и острова; на SE 3 над формой пустые 26 pt. Заголовок «Новая съёмка» по той же причине на y = 104 на всех моделях. Правка: отступ = измеренная верхняя зона + 8 (читать её `onGeometryChange` у корня формы; он там уже есть на строке 89). **small.**

**П2. Панель вкладок — фиксированная высота 84 pt, а не «содержимое + полоса домой».** Измерено: над полосой «домой» панель видна 50 pt на всех Pro и 84 pt на SE 3 (там полосы нет) — на 667 pt это +34 pt (5 % экрана). `TabBarView.swift:24` (`static let height = 84`), `RootView.swift:164–172` (внутри — `84 − bottomInset`), `BinFlight.swift:14` (тот же 84 + 26 для круга корзины). Правка: высота панели = 50 + измеренная нижняя зона. **small–medium** (затрагивает круг корзины, нижнюю кромку свода карты и `timebarTop` — они уже читают `tabbar` как узел). Для Duo панель, нарисованная вручную, сама на бок не уйдёт (раздел 5).

**П3. AR: список «Слоёв» без прокрутки и без потолка по высоте.** Измерено: список 91…541 pt, нижняя панель стоит с 496 → налезание **44 pt** на SE 3; на Pro зазор 50–132 pt. На внешнем экране Duo (678 pt) будет так же. Причина: `SunARLayersButton.swift:107–115` — обычный `VStack`, ширина 320 фиксирована. Нижняя панель и зоны экрана в `SunARScreen.swift` уже считают по измеренной `panelHeight`, список — нет. Правка: оборнуть ряды в `ScrollView` с высотой ≤ (верх панели − верх списка − 8). **small.**

**П4. Карточка на 375 pt: лента точек дня обрезана, телефон в плитке переносится.** Видно на кадре: пятая точка «Банкет 19:30» не поместилась (`CardDayTile.swift:270–315` — у точек колонка фиксированной ширины `w`); номер «+7 961 887-80-78» в плитке студии идёт в две строки. Pro не затронуты (393 и шире — 5 точек помещаются). Правка: ширина колонки по измеренной ширине плитки / горизонтальная прокрутка ленты. **small–medium.**

**П5. Короткая карточка на высоких экранах: полэкрана пусто.** «Пейзаж» после съёмки: блоки кончаются на y = 497 из 852 (пусто 355 pt, 42 %) на 15 Pro и y = 500 из 956 (456 pt, 48 %) на 17 Pro Max; кнопка «Удалить» висит посередине. Это не ошибка вёрстки (содержимого мало), но высота не используется. Правка (по слову Алексея): прижать «Удалить» к низу или оставить как есть. **small, решает Алексей.**

**Мелочи (low).**
- Лист «Мудборда» `MoodboardSheets.swift:80`: `min(height, 700)` — жёсткие 700 pt, не доля окна; на 667 (SE, Duo внешний) 700 > окна, остальные листы режут по 86 % (`PlannerBlockSheet.swift:105`, `PlannerLayers.swift:253`, `PlaceSheet.swift:121–123`, `CardQuest.swift:179`). Не снято (сцен с этим листом в наборе нет). **small.**
- `FormKit.swift:349` (`.height(400/468)`) и `:447` (`.height(300)`) — листы выбора даты и ещё одного выбора с фиксированной высотой; на 667 влезают (468 < 86 % окна), на Duo внешнем тоже. **small.**
- Знакомство: заголовок системного листа обрезан на 375 (системное поведение, `SettingsPieces.swift:117+`). **small.**
- Окно «Мудборд → папка» на SE 3 и 15 Pro в рамках отдаёт ширину 402 при экране 375/393 (узкие чипы-фильтры — горизонтальная лента). На кадре выхода за край нет; причина не установлена, остаётся замером без вердикта.
- Свод карты на 15 / 17 Pro режет нижний ряд пополам (1 ряд из 8 за краем) (прокрутка есть: `MapScreenView.swift:578–585`, высота `min(contentHeight, foldMax)` — это образец «по измеренному месту»). Подсказки прокрутки нет. **small**, по желанию.
- Стартовые значения `@State` до первого замера: `MapScreenView.swift:20–28` (150 / 760 / 60 / 700), `:68` (700), `RootView.swift:240`, `FormScreen.swift:24`, `CardQuest.swift:124` (956), `MapKitCanvas.swift:17` (440), `SunARScreen.swift:51` (200), `PlannerBlockSheet.swift:16` (600), `PlannerLayers.swift:211,302`. Действуют один кадр; безвредны, но привязаны к 17 Pro Max (956 / 440).

## 5. Duo и размерные классы (по коду, не по снимкам)

- `Config/iOS.xcconfig:6` `TARGETED_DEVICE_FAMILY = 1`, `:16` `UISupportedInterfaceOrientations = Portrait`: приложение только iPhone-портрет; Duo-размеры не заявлены.
- `horizontalSizeClass` / `verticalSizeClass` нигде в `Packages/` не читаются. Все экраны считают место по `GeometryReader` / `onGeometryChange` у корня — это хорошая основа, но «компактная/обычная ширина» в коде не существует.
- Нижняя панель (`TabBarView`, `RootView.swift:164`) нарисована вручную, не `TabView`: система не переведёт её в боковую панель на Duo/iPad. Тот же вопрос у «дома» карты и таймбара (`MapScreenView.swift:120`, `timebar` 96 pt), нижней панели AR (`SunARScreen.swift:181`) и «Вернуть» (`UndoBar`).
- Фиксированные ширины, зависящие от экрана: `SunARLayersButton.swift:115` (320), `MapSpots.swift:540` (меню 216–280, высота ≤ 320), `CardQuest.swift:52` (QR 232×232), `PlaceSheet.swift:377` (список ≤ 168), `OrgCardScreen.swift:145` (поле 190), `FormPlace.swift:302` и `FormScreen.swift:367` (барабан 140), месяц `PlannerMonthView.swift:99` (клетка 58 → плита 347 pt), сетка дня `PlannerDayView.swift:97,169` (час × 25).
- Внутренний экран Duo 669 pt шириной — шире всех моделей. Проверить придётся реальным размером (Xcode: Duo-симулятор или окно iPad/Мак с нужным размером, как только стабильный Xcode его даст) — сейчас инструмента нет.

## 6. План правок (по важности для Pro, затем для Duo)

1. П1 — форма: верх по измеренной зоне. small.
2. П2 — панель вкладок: 50 + нижняя зона вместо 84. small–medium.
3. П3 — AR-список «Слоёв»: прокрутка с потолком по месту. small.
4. П4 — карточка 375: лента точек и телефон по ширине. small–medium.
5. Мелочи (листы 700 / 400 / 468 / 300 → доля окна). small.
6. П5 — решить словом: оставить или прижать «Удалить» к низу. small.
7. Duo: сначала размерные классы и снятие «только портрет» (large), потом — заменить самодельную панель вкладок на адаптивную (large), и сквозной прогон `Tools/audit_heights/run.js` с Duo-размерами, когда появится способ их задать.

## 7. Что осталось не проверено

- Duo (оба экрана), 16 Pro / 16 Pro Max / 18 Pro отдельно (по размеру совпадают с 17 Pro / 17 Pro Max), «Свет», светлая тема на остальных сценах.
- Клавиатура: сцены с открытой клавиатурой (форма, поиск) не снимались; в одном кадре «Поиск» поверх симулятора лежит системная подсказка клавиатуры («Speed up your typing…») — артефакт симулятора, не приложения.
- Поведение приложения под SDK Xcode 27.1 (сборка осталась на 26.6).
- Промах по ходу: `simctl shutdown all` выключил общий `iPhone 17 Pro Max` — включён обратно; «LP …» симуляторы гасит `light_fit` у других сессий, поэтому симуляторы аудита названы `Audit-*`.

## 8. Как повторить

```
xcodebuild … -derivedDataPath <dd> build        # Debug-сборка симулятора
xcrun simctl create "Audit-A15P" com.apple.CoreSimulator.SimDeviceType.iPhone-15-Pro com.apple.CoreSimulator.SimRuntime.iOS-26-5   # и так для A17P, A15PM, A17PM, ASE3
node Tools/audit_heights/run.js --app <dd>/Build/Products/Debug-iphonesimulator/LightPlan.app --out <out> [--themes dark,light] [--scenes …]
python3 Tools/audit_heights/analyze.py <out>                      # таблица по рамкам
python3 Tools/audit_heights/montage.py <out> <файл.png> A15P+A17PM map,map_fold 0.3   # кадры рядом
```
