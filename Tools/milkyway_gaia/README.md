# Млечный Путь из каталога Gaia DR3

Два файла для слоя AR «Млечный Путь»: **россыпь реальных звёзд** G ≤ 10 точками (`stars_gaia.bin`) и **карта
свечения** всех более слабых звёзд Gaia до G = 21 по небу (`milkyway_glow_gaia.png`). Ни фото, ни шума, ни модели:
каждая точка и каждая ячейка карты — сумма настоящих звёзд каталога Gaia DR3 (ESA). Тёмные облака пыли видны
как места, где звёзд меньше. Решение Алексея 20.10.2026 (`Light_Plan/DECISIONS.md`): карта модели Галактики
(PR #5, ветка `claude/milkyway-model-dtw3cp`) вышла слишком гладкой — «градиенты, будто в расфокусе».
Приложение читает эти файлы шейдером Metal; здесь только данные и картинки для просмотра.

```
make milkywaygaia                                   сборка + картинки + проверка + повтор прогона (~2 мин, без сети)
python3 Tools/milkyway_gaia/fetch.py                скачать сырой кэш в raw/ (сеть, ~15 мин; докачивает недостающее)
python3 Tools/milkyway_gaia/build.py [--out DIR] [--color flux|count]     только сборка
python3 Tools/milkyway_gaia/validate.py [--repeat DIR]                     только проверка
python3 Tools/milkyway_gaia/preview.py                                     только картинки
```

Нужны `python3`, `numpy`, `Pillow`; для `fetch.py` ещё `requests`. Сырой кэш `raw/` (290 МБ) в репозиторий не
кладётся (`.gitignore`); без него `build.py` выходит с кодом 2 и подсказкой. Сейчас `make milkywaygaia`
кончается кодом 1: одна проверка — «НЕТ» (размер PNG, см. «Отступления»).

## Что получает приложение (подробно — `spec.json`)

### `stars_gaia.bin` — точки

Все 482 106 источников Gaia DR3 с `phot_g_mean_mag ≤ 10` (сервер: `COUNT(*)` = 482 106, у 481 812 есть BP−RP).
Little-endian. Заголовок 16 байт: `"LPGS"`, `uint16 version = 1`, `uint16 record_size = 8`, `uint32 count`,
`uint16 g_limit_x10 = 100`, `uint16 0`. Затем записи по 8 байт:

| Смещение | Тип | Поле | Как читать |
|---|---|---|---|
| 0 | uint16 | l | l° = raw · 360 / 65536 (шаг 0,0055°) |
| 2 | int16 | b | b° = raw · 180 / 65536 (шаг 0,0027°) |
| 4 | uint8 | G | G = raw / 10 |
| 5 | int8 | BP−RP | BP−RP = (raw + 0) / 10, −12,8…+12,7 (у звёзд файла −0,89…+8,23, обрезанных нет) |
| 6 | uint8 | флаги | бит 0: у звезды нет BP−RP, записана медиана BP−RP звёзд с той же G (интервал 0,5) — 294 звезды |
| 7 | uint8 | резерв | 0 |

В Metal: `struct { ushort l; short b; uchar g; char bp_rp; uchar flags; uchar pad; }`, буфер со смещением 16.
Записи идут **от ярких к слабым** (при равной G — по `source_id`), так что «звёзды до G = m» — это первые N записей.
Ошибка упаковки: по l до 0,00275°, по b до 0,00137°, по G до 0,05.

**Ярче G ≈ 3 Gaia неполна** (насыщение детектора): таких в файле 150, их фотометрия и даже наличие ненадёжны,
самая яркая — G 1,73. Самые яркие звёзды неба даёт каталог приложения (`ConstellationCatalog` + `BrightStars`,
V ≤ 2,5); звёзды ярче G 3 отсюда лучше не рисовать или снимать дубли по расстоянию. Положения — эпоха J2016.0,
собственное движение не учтено: за 10 лет сдвиг больше половины шага упаковки (≈ 10″) только у 163 звёзд
быстрее 1″/год.

### `milkyway_glow_gaia.png` — свечение

- **Что в пикселе.** Все 1 736 201 948 источников с 10 < G ≤ 21 (у 1 485 912 576 есть BP−RP), сложенные по
  ячейкам 0,125° сервером ESA: `SUM(POWER(10, −0.4·G))`, `COUNT(*)`, суммы BP−RP. Значение пикселя —
  **поверхностная яркость**: поток ячейки, делённый на её телесный угол (иначе карта темнела бы к полюсам, где
  ячейки plate carrée в cos b раз меньше по площади). Яркость Y = 0,2126 R + 0,7152 G + 0,0722 B. Максимум канала
  по карте = 1,0 (65535) — это шаровое скопление 47 Тукана (l 305,9°, b −44,9°); медиана Y — 0,5 % максимума.
- **Шкала.** 1,0 = поток звезды **G = 0,82 на квадратный градус** (`spec.json → glow.scale`): так свечение и точки
  `stars_gaia.bin` ставятся в одну физическую шкалу.
- **Оси — как у карт NASA SVS.** `u = fract(0.5 − l/360)`: l = 0 посередине, **долгота растёт влево**, края u = 0
  и 1 — l = 180°. `v = 0.5 − b/180`: сверху северный полюс Галактики. Значение — в центре пикселя: столбец i —
  l = 180° − (i + 0,5)·0,25°, строка j — b = 90° − (j + 0,5)·0,25°. Читать билинейно, по u — с повтором.
- **Полюса.** Где ячейка 0,125° уже 0,125° · cos b, в неё попадает меньше звезды и карта шумит; там соседние
  ячейки по долготе объединены (окно — нечётное round(1/cos b), начиная с |b| ≈ 48,3°), чтобы настоящая ширина
  была не меньше 0,125°.
- **Цвет.** Средний BP−RP ячейки **по потоку** (Σ F·(BP−RP) / Σ F) → B−V → температура чёрного тела → линейный
  sRGB с белой точкой «чёрное тело 5800 K = (1, 1, 1)» (дневной баланс белого); оттенок нормирован на Y = 1,
  яркость — поверхностная яркость. Ячейка, где звёзд с цветом меньше 10, берёт цвет из карты, сглаженной σ 0,5°
  (0,001 % ячеек). Почему по потоку, а не AVG(bp_rp) — в «Отступлениях».
  - BP−RP → B−V: медианы B−V у 78 543 звёзд Hipparcos (e(B−V) < 0,03, G > 4) в интервалах BP−RP по 0,1,
    неубывающие (у M-звёзд B−V перестаёт расти около 1,64); таблица — в `spec.json`.
  - B−V → T: T = 4600 K · (1/(0,92(B−V) + 1,7) + 1/(0,92(B−V) + 0,62)) (Ballesteros 2012, EPL 97, 34008).
  - T → sRGB: спектр Планка × кривые сложения CIE 1931 в приближении Wyman, Sloan & Shirley 2013 (JCGT 2(2)) →
    XYZ → линейный sRGB. Солнце (BP−RP 0,82) → 5770 K → белое; BP−RP 0 → 10 300 K, голубоватое; 2,0 → 3600 K.
  - Тем же правилом приложение может красить точки `stars_gaia.bin` (так сделано в картинках).

### Тонирование (для картинок; в шейдере — решать там)

`I_out = 1 − exp(−k·I)` по яркости Y, оттенок сохраняется: `out_c = I_c · (1 − exp(−k·Y)) / Y`. k = 3,244 —
так, что ядро (99,9-й перцентиль сглаженной σ 1° яркости в |l|, |b| ≤ 10°, Y = 0,2825) даёт 0,6. Как и в PR #5,
тонированное значение пишется в 8 бит напрямую, без кривой sRGB: на картинке ядро — 153 из 255. Слой AR в
приложении рисуется в буфер `.bgra8Unorm` (`SunARLens.swift`), то есть тоже без кривой sRGB.

## Как считается

1. **Яркие звёзды** — 7 запросов по срезам G (≤ 6, 6–7, 7–8, 8–8,5, 8,5–9, 9–9,5, 9,5–10) + контрольный
   `COUNT(*)`; `build.py` останавливается, если сумма срезов не равна счёту сервера.
2. **Свечение** — 192 запроса `GROUP BY FLOOR(l*8), FLOOR((b+90)*8)` (ровно `FLOOR(l/0.125)`: 0,125 — степень
   двойки), каждый по своему куску неба: пиксель HEALPix уровня 2 = диапазон `source_id` (в Gaia `source_id`
   кодирует место на небе). Вместо `AVG(bp_rp)` сервер отдаёт `SUM(bp_rp)` и `COUNT(bp_rp)` — ячейка на границе
   двух кусков приходит из обоих, а суммы складываются, средние нет. Плюс `SUM(F·bp_rp)` и
   `SUM(F·(bp_rp·0+1))` — для цвета по потоку (`CASE` парсер ADQL сервера не принимает, а `bp_rp*0+1` равно NULL
   у звезды без цвета, и `SUM` его пропускает). Кусок считается 4–33 с; всё небо — 8,7 мин в 3 потока.
3. **Контроль полноты** — ещё 12 запросов `COUNT(*)` по пикселям HEALPix уровня 0: в каждом сумма наших ячеек
   совпала со счётом сервера, всего 1 736 201 948 = 1 736 201 948.
4. **Цвет** — 99 390 пар «B−V Hipparcos — BP−RP Gaia» одним запросом через официальную таблицу соответствия.

**Ограничения архива, найденные по ходу** (20.10.2026, анонимный доступ): без параметра `MAXREC` ответ молча
обрезается на 50 000 строк (так в первом прогоне обрезались три среза ярких звёзд — заметил по расхождению с
`COUNT(*)`: 256 364 против 482 106); `/capabilities` пишет `outputLimit` 50 000, но с `MAXREC` сервер отдаёт больше
(проверено до 187 859). Одно задание живёт не дольше 600 с (`executionDuration`). `fetch.py` шлёт `MAXREC =
3 000 000` и считает ответ ровно в `MAXREC` строк обрезанным.

## Проверка

Определения зафиксированы в `validate.py` до первого прогона; единственное изменение — (д), см. ниже.

| Проверка (порог задачи) | Значение | Итог |
|---|---|---|
| `stars_gaia.bin` ≤ 5 МБ | 3,86 МБ | да |
| `milkyway_glow_gaia.png` ≤ 2,5 МБ | **4,41 МБ** при 1440 × 720 (2880 × 1440 — 15,63 МБ) | **НЕТ** |
| Повторный прогон `build.py` | побайтно то же (bin, png, spec) | да |
| (а) звёзд G ≤ 10: 400–600 тыс. и = `COUNT(*)` сервера | 482 106 = 482 106 | да |
| (б) корреляция log яркости с NASA SVS 1024 × 512 (≥ 0,9) | r = 0,998 (Спирмен 0,985, наклон log–log 1,16) | да |
| (в) ядро: максимум сглаженной (σ 1°) яркости на \|l\| ≤ 3° | l +2,1°, b −3,4° | да |
| (г) Угольный Мешок: кольцо 3°–5° / круг 1° вокруг (303°, 0°), ≥ 1,3 | 1,91 | да |
| (г) Большой разлом, l 10°–50°: \|b\| 2°–5° / \|b\| ≤ 1°, ≥ 1,3 | 1,51 (по градусам l: медиана 1,66, от 0,76 до 4,14) | да |
| (д) БМО: местный максимум ≤ 1° от (280,5°, −32,9°) | 0,11° (пик к кольцу 6°–8° — 9,9) | да |
| (д) ММО: местный максимум ≤ 1° от (302,8°, −44,3°) | 0,18° (пик к кольцу — 8,7) | да |
| (е) 20 звёзд против SIMBAD: ≤ 0,02° и ≤ 0,15 mag | 20/20; макс 20,2″ и 0,049 mag | да |
| Матрица ICRS → галактические против l, b самой Gaia | 0,00000″ на 6764 звёздах | да |

- **(б)** Обе карты сглажены гауссом σ 1°, наша взята в центрах пикселей NASA, вес cos b; JPG NASA расшифрован
  кривой sRGB (как в PR #5; у модели PR #5 было 0,959). Корреляция так высока потому, что судья **тоже построен из
  Gaia** (DR2, без ярких звёзд Hipparcos/Tycho — как и наша карта без G ≤ 10): проверка подтверждает оси, шкалу
  и сборку, но не независима от каталога.
- **(в)** Максимум ниже плоскости на 3,4° — окно Бааде / облако Стрельца; в самой плоскости у центра пыль. У карты
  NASA максимум там же (PR #5: l 2,3°, b −3,7°).
- **(г)** На отдельных градусах долготы разлом «не виден» (0,76 — звёздное облако или скопление прямо в плоскости),
  но в среднем по 10°–50° и в медиане — да.
- **(д) — определение изменено после первого прогона.** Сначала искался самый яркий пиксель в круге 3° вокруг
  ожидаемой точки. У ММО им оказалось шаровое скопление **47 Тукана** (l 305,9°, b −44,9°) — в 2,26° от центра
  ММО и ярче него, проверка вышла «НЕТ». Задача требует «локальный максимум в пределах 1°»; теперь проверяется ровно
  это (пиксель, ярче которого нет ничего в радиусе 1° вокруг него). Прежний результат печатается рядом, в скобках.
- **(е)** 20 звёзд: 5 интервалов G (3–5, 5–6,5, 6,5–8, 8–9, 9–10) × 4 интервала |b| (0–5°, 5–20°, 20–50°, 50–90°), в
  каждом — звезда с наименьшим `source_id mod 1 000 003`. Сравнивается запись `stars_gaia.bin` (после упаковки) с
  координатами SIMBAD, переведёнными в галактические, и G SIMBAD. Самое большое расхождение 20,2″ — HD 192310,
  близкий карлик с собственным движением 1,26″/год по Gaia DR3 (SIMBAD даёт J2000, Gaia — J2016). **Оговорка:** SIMBAD берёт
  для этих звёзд координаты и G из самой Gaia (EDR3 `2020yCat.1350....0G`, у трёх G — DR3 `2022yCat.1355....0G`),
  так что проверка подтверждает нашу цепочку «скачал → упаковал → прочитал», а не каталог Gaia.
- **Цвет против NASA** (справочно, без порога; R/G и B/G в линейном свете): ядро 1,42 / 0,56 против 1,50 / 0,77;
  полоса l 100°–260° 1,19 / 0,77 против 1,10 / 0,89; |b| 20°–40° 1,11 / 0,85 против 1,00 / 0,96; полюса 1,08 /
  0,90 против 1,00 / 1,00. Наша карта чуть теплее (белая точка 5800 K), ход по небу тот же.

## Отступления от задания

1. **PNG не влез в 2,5 МБ даже после понижения.** 2880 × 1440 — 15,63 МБ, по правилу задачи понижено до
   1440 × 720 — **4,41 МБ**. Вес — это сама россыпь: поток ячейки часто задают одна-две звезды 10–13m, и 16 бит
   хранят её точно, а три канала RGB кодируются независимо. Замеры на той же карте 1440 × 720: округление до 8
   значащих бит — 4,10 МБ, до 6 — 3,25 МБ; цвет, сглаженный σ 0,5°, — 4,15 МБ; **одна яркость (серый 16 бит) —
   1,56 МБ**. Что выбрать — решать Алексею: (а) принять 4,4 МБ; (б) хранить яркость серым 16 бит + цвет отдельной
   маленькой картой (≈ 1,6 МБ + цвет); (в) 2880 × 1440 (15,6 МБ), если важна резкость при увеличении — разницу
   видно в `zoom_core_20x13*.jpg`. Полная сетка лежит в `raw/milkyway_glow_gaia_2880x1440.png` и собирается тем же
   `make`.
2. **Цвет — средний по потоку, а не `AVG(bp_rp)`.** Средний по числу звёзд задают слабые звёзды 18–21m: их больше
   всех, их BP−RP шумный, и в сумме свет от них мал. Замер против карты NASA (R/G, B/G): по числу — у полюсов 1,29
   / 0,65, в полосе 1,35 / 0,60 (всё небо оранжевое); по потоку — 1,08 / 0,89 и 1,19 / 0,77; NASA — 1,00 / 1,00 и
   1,10 / 0,89. Средний BP−RP у полюсов: по числу 1,46, по потоку 1,00. Вариант задачи собирается так:
   `build.py --color count`; суммы для обоих лежат в `raw/glow_grid.npz`.
3. **Куски запросов — пиксели HEALPix (диапазоны `source_id`), а не полосы по долготе.** `source_id` проиндексирован
   и задаёт место на небе, поэтому кусок считается за секунды; полоса по l заставила бы сервер 36 раз читать все
   1,8 млрд строк. Срезы по величине — только для ярких звёзд (там у сервера индекс по G).
4. **В пикселе — поверхностная яркость, у полюсов ячейки объединены по долготе** (см. «Свечение»). Без этого «сумма
   потока в ячейке» темнела бы к полюсам как cos b, а у самого полюса ячейка — доля звезды.
5. **Запись 8 байт:** в задании перечислено 7 (2 + 2 + 1 + 1 + 1), восьмой байт — тоже резерв (0); байт 6 занят
   флагом «цвет по умолчанию». **Смещение BP−RP — 0:** int8 со знаком в десятых и так покрывает −12,8…+12,7, а у
   звёзд файла −0,89…+8,23; поле смещения есть в `spec.json` (`offset_tenths`), чтобы его можно было ввести.
6. **Проверка (д)** — определение изменено после первого прогона (см. «Проверка»).
7. **Картинки** — без кривой sRGB (как PR #5 и как буфер AR приложения), JPEG вместо PNG; добавлена вторая
   «увеличенная» картинка из полной сетки.

## Что не проверено

- **Вид на телефоне, шейдер приложения, производительность GPU.** Здесь только файлы и картинки на ПК. Для GPU:
  в Metal нет 16-битного RGB без альфы — карта 1440 × 720 станет `rgba16Unorm`, 8,3 МБ видеопамяти (2880 × 1440 —
  33 МБ); 482 106 точек — 3,9 МБ буфера. Как их рисовать (порог по G, размер точки, сложение с камерой) — шаг
  приложения.
- **Полнота Gaia в тесных полях.** В балдже Gaia теряет звёзды слабее G ≈ 18–20 (предел плотности источников); на свечение это
  влияет мало (поток дают звёзды 10–16m), но точно не измерено. Полосы закона сканирования Gaia на слабых величинах
  на картинках не заметны; отдельно не проверялись.
- **Цвет.** Белая точка 5800 K — выбор (как в PR #5); B−V для красных звёзд обрезан на 1,64 (≈ 3600 K). Звёзды ярче
  G 3 не проверялись (их в приложении даёт свой каталог).
- **Резкость при сильном увеличении.** Даже полная сетка 0,125° при поле 20° — 11 экранных пикселей на ячейку;
  для «телефото» в AR нужна либо мельче сетка, либо больше точечных звёзд (G ≤ 11 — 1 247 240 звёзд по `COUNT(*)` сервера, 10,0 МБ).
- Лицензия — прочитана и процитирована, юридически не проверялась.
